# แดชบอร์ดสถิติหวยไทย

### ▶ [รัน backtest ในเบราว์เซอร์](https://olay097056.github.io/thai-lottery-stats/demo/)

โหลด `static/formula-engine.js` ตัวจริงจาก repo นี้ ไม่ได้เขียนใหม่ให้ demo
แล้วให้คะแนนทุกสูตรกับผลรางวัลจริง 780 งวด ลองสลับช่วงทดสอบระหว่าง 50 ถึง 400 งวด
แล้วดูว่าสูตรไหนรักษา Edge ไว้ได้ ส่วนใหญ่รักษาไม่ได้

---

แดชบอร์ดวิเคราะห์สถิติและช่วยตัดสินใจสำหรับหวยรัฐบาลไทย สร้างขึ้นเพื่อตอบคำถามเดียว
อย่างตรงไปตรงมาว่า **สูตรหวยพวกนี้ชนะการสุ่มได้จริงไหม**

คำตอบที่แอปนี้ไปถึงคือ *ส่วนใหญ่ไม่ได้* และนั่นแหละคือประเด็น

แทนที่จะทำเครื่องมือทำนายที่เอาใจผู้ใช้ โปรเจกต์นี้เอาทุกสูตรไป backtest กับผลรางวัลจริง
ย้อนหลัง 780 งวด แล้วรายงานค่า **Edge** คือความแม่นยำลบด้วยเส้นฐานของการสุ่มสำหรับ
การแทงประเภทนั้น สูตรไหนผ่านเกณฑ์ไม่ได้จะติดป้าย **ทดลอง** ถาวร ไม่ได้ถูกลบทิ้งเงียบๆ

## ทำอะไรได้บ้าง

- **ดึงและแคชผลหวย 780 งวด** จาก 2 แหล่ง (myhora.com สำหรับรางวัลหลัก และ
  news.sanook.com ผ่าน JSON-LD สำหรับรางวัลที่ 2–5) ได้ตารางรางวัลครบ
  ไม่ใช่แค่เลขรางวัลที่ 1
- **เครื่องทำนายเชิงสถิติ** คิดคะแนนรวมจาก 9 สัญญาณ เช่น ความถี่วันและเดือนเดียวกัน,
  วันในสัปดาห์, ความถี่ถ่วงน้ำหนักตามความใหม่, ความน่าจะเป็นร่วมของหลักตัวเลข,
  เลขที่ไม่ออกนาน และหักคะแนนถ้าเลขนั้นเพิ่งออกงวดที่แล้ว
- **Beam search สำหรับรางวัลที่ 1** แยกเลข 6 หลักเป็นหน้า3 กับหลัง3 ให้คะแนนแต่ละครึ่ง
  ภายใต้ 3 ชุดน้ำหนัก แล้วรวมอันดับด้วยค่าเฉลี่ยฮาร์มอนิก
- **สูตร 11 กลุ่ม (A–J, HM)** ผสมระหว่างสูตรหวยพื้นบ้านที่ถอดออกมาเป็นโค้ด
  กับสูตรที่ค้นพบเองจากการค้นหาอย่างเป็นระบบบนตระกูลสมการที่ประกาศไว้ก่อน
- **เครื่อง backtest ที่หักลบเส้นฐาน** ทุกสูตรถูกตรวจกับช่องรางวัลที่มันอ้างว่าเล็งไว้เป๊ะๆ
  (`bottom2`, `top3`, `back3`, `pool6`, `pool14_tail3` และอื่นๆ) เพราะการเอาเลข 2 ตัว
  ไปเทียบอัตราถูกกับเลข 6 ตัวแบบดิบๆ ไม่มีความหมาย
- **หน้าจัดชุดซื้อ** แปลงเลขที่แนะนำเป็นแผนใช้เงินจริง พร้อมบัญชีกำไรขาดทุนและ
  ค่าคาดหวังที่ไม่โกหก ตัวเลขพาดหัวคือ EV ทางคณิตศาสตร์ล้วนๆ (−5% ต่อบาทสำหรับ
  แทงรายเลข และราว −40% ต่อใบลอตเตอรี่) ส่วนตัวเลขที่ปรับด้วย backtest จะขึ้น
  คำเตือนเรื่อง noise ทุกครั้งที่มันเผลอเป็นบวก
- **Track record** ทุกครั้งที่เปิดหน้าสรุป ระบบบันทึกเลขที่แนะนำอัตโนมัติ
  อัตราถูกของแดชบอร์ดเองจึงถูกพล็อตเป็นกราฟย้อนหลัง และไม่มีทางถูกลืมเงียบๆ

## ทำไมต้องมีกลไกความซื่อสัตย์พวกนี้

การ backtest บนพื้นที่ค้นหาขนาดนี้ทำให้พลาดได้ 2 แบบคลาสสิก โครงสร้างโค้ดจึงวางไว้
กันทั้งสองอย่าง

**วินัยเรื่อง holdout** ข้อมูลช่วงท้ายที่ใหม่ที่สุดจะไม่ถูกแตะระหว่างค้นหาสูตรเลย
มันถูกประเมินครั้งเดียว เพื่อให้ค่า Edge ที่ใช้ตัดสิน Promotion Gate ใช้ไปแล้วก็หมดสิทธิ์
เป็น holdout อีก

**สูตรที่ผ่านเกณฑ์ไม่ได้โดยธรรมชาติ** บางสูตรเล็งช่องรางวัลที่จับฉลากเป็นเลขสุ่มอิสระ
มีประวัติมากแค่ไหนก็แยกฝีมือออกจากดวงไม่ได้ สูตรพวกนั้นจึงติดป้ายทดลองถาวร
ไม่ได้เอามาจูนไปเรื่อยจนตัวเลขดูดี

มีสูตรหนึ่ง (HM3) วัดได้ 9 ครั้ง เทียบกับค่าคาดหวัง 9.1 ครั้ง ตรงตามฟิสิกส์เป๊ะ
ผลนี้ถูกบันทึกไว้ในฐานะ*ความสำเร็จของวิธีการ* ไม่ใช่ซุกไว้ในฐานะความล้มเหลวของสูตร

สูตรที่สอบตก holdout (J1 ได้ +1.67% บนชุด validation แต่ **−0.21%** บน holdout)
ยังอยู่ในแอปใต้ป้ายทดลอง พร้อมโชว์ตัวเลขจริงนั้น ส่วนสูตรรุ่นก่อนชื่อ FABLE
ถูกปลดระวางไปเลยหลังสอบตกเกณฑ์เดียวกัน

เหตุผลเบื้องหลังกฎเหล่านี้เขียนเป็น ADR ไว้ใน [`docs/adr/`](docs/adr/)

## เทคโนโลยีที่ใช้

| ส่วน | เทคโนโลยี |
|---|---|
| Backend | Python 3.11, FastAPI, pandas |
| Frontend | Vanilla JS SPA ไม่มี build step, Chart.js |
| ML | scikit-learn (GBM) คง endpoint ไว้อ้างอิง ไม่ได้แสดงบน UI |
| Scraping | requests + BeautifulSoup แคชแบบ incremental ลง CSV |
| Tests | ดึงฟังก์ชันบริสุทธิ์ออกมารันด้วย Node `vm` ขับด้วย fixture |

ตรรกะการจัดสรรเงินและการเคลียร์ผลถูกแยกออกมาเป็นฟังก์ชันบริสุทธิ์ 2 ตัวโดยตั้งใจ
คือ `bpBuildPlan(input) → plan` กับ `bpResolvePlan(plan, drawResult) → resolution`
เพื่อให้คณิตศาสตร์เรื่องเงินทดสอบได้โดยไม่ต้องมี DOM และไม่ต้องต่อเน็ต

## วิธีรัน

```bash
pip install -r requirements.txt
uvicorn main:app --port 8509 --reload
```

แล้วเปิด <http://localhost:8509> ไฟล์แคชผลหวย (`lottery_cache.csv`) ลบทิ้งได้
เดี๋ยวมันดึงใหม่เองตอนโหลดรอบถัดไป

## โครงสร้างโปรเจกต์

| ไฟล์ | หน้าที่ |
|---|---|
| `main.py` | FastAPI app และ endpoints |
| `analyzer.py` | การทำนายเชิงสถิติ คะแนนรวม, beam search, เลขร้อนเย็น, เลขไม่ออกนาน |
| `scraper.py` / `sanook_scraper.py` | ดึงข้อมูลจากสองแหล่ง |
| `ml_predictor.py` | เทรนและทำนายด้วย GBM |
| `static/formula-engine.js` | สูตรคำนวณทั้งหมด รวมถึงเครื่อง backtest |
| `static/app.js` / `app.css` | ตรรกะ SPA และธีม macOS dark |
| `docs/adr/` | บันทึกการตัดสินใจเชิงสถาปัตยกรรม |

## ข้อความปฏิเสธความรับผิดชอบ

การออกรางวัลหวยเป็นการสุ่ม ไม่มีอะไรใน repo นี้ทำนายมันได้ และ backtest ทั้งหมด
อยู่ตรงนี้ก็เพื่อแสดงข้อเท็จจริงข้อนั้นพอดี

นี่คือโปรเจกต์วิเคราะห์ข้อมูลและความเข้มงวดทางสถิติที่บังเอิญใช้ข้อมูลหวยเป็นหัวข้อ
ตัวเลขใดๆ ที่มันสร้างออกมา ขอให้ถือเป็นความบันเทิง ไม่ใช่คำแนะนำ
